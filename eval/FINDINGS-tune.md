# Tune-split findings, 2026-11-07

What the 44 tune cases of the current-state set show, read from the stored
runs in `eval/runs/`. The numbers are in `REPORT-tune.md`, generated by
`eval report`. Pass 1 and its report are kept in `REPORT-tune-pass1.md` and in
git history. The 22 holdout cases have **not** been run; they wait until the
labels are reviewed and the thresholds are frozen.

**Basis: current state** (docs/DECISIONS.md L26). Each token was checked as it
is today, so this measures whether Skein would stop the listing now, not
whether it would have caught the token before its event. Policy:
`dex-list@0.2.0`, with no context (no repository or social handle), so code
review and social bots were never bought.

Skein's blockers and its abstain rule are what keep bad tokens out. Without
them, the same paid findings averaged approve between one bad token in six and
one in three. The price is abstention: about a third of verdicts decline to decide.

## Why it abstains (pass 2)

1. **No DEX pool (rugged tokens).** The resolver finds no pair for most of the
   documented rugs, because their markets are gone. Liquidity is then never
   bought, and a required check is missing, so Skein abstains. A missing
   market is real evidence, but it comes from a free DEX Screener lookup, not
   a paid Telegraph answer. Treating it as a FAIL is a policy choice to make
   on purpose, not a tuning shortcut.
2. **No holder count on BNB Chain.** Neither allowlisted holder-count miner
   (TxLens 9002, ChainWire 7302) counts BNB Chain holders: every BNB case came
   back null. This is a coverage gap on the network. GoPlus does return a
   holder count inside its audit answer, but it is not registered for the
   holder-count intent.
3. **GoPlus rate limits.** Its upstream answered "too many requests" on 7
   pass-1 cases. 13 cases were rerun after the fix below, and those answered.

## What changed between passes

The pipeline used to stop at a miner that failed before payment, such as
TxLens's 503 "try again later". Such a failure costs nothing, so the next
allowlisted miner is now tried. The 13 tune cases that hit TxLens or GoPlus
errors were rerun (`eval run --ids`). Tune cases may be rerun; holdout cases never are.

## False rejects

Two good tokens were rejected: VIRTUAL (Base) and GMX (Arbitrum). In both,
GoPlus flags `hidden_owner` and `owner_change_balance`: owner or handler
powers over balances that these contracts really have. Under `dex-list` that
is a hard audit FAIL. Whether a listing policy should block on those flags for
admin-governed tokens is a threshold decision for the owner, made on the tune
split before the holdout run.

## Before the holdout run

- Review the labels (guide 3, "What is left for you").
- Decide the two policy questions above (missing pool, owner-power flags) and
  freeze them in a new policy version.
- Then run the holdout split once:
  `eval run eval/cases.json --split holdout … --max-total-usdc 2`.
